1. EXECUTIVE ARCHITECTURE OVERVIEW
================================================================================
The Elsewedy SEDCO application is a "Serverless" static site augmented by a powerful Backend-as-a-Service (BaaS) via Supabase and a completely custom Local Storage-based Content Management System (CMS).

- The Frontend relies on static HTML, CSS, and Vanilla JS, maximizing performance and minimizing server overhead.
- The Backend logic, Database, and Authentication are outsourced to Supabase.
- The custom CMS allows administrators to click, edit, and instantly deploy visual changes by overriding HTML structures via JSON stored in the browser. 

The application removes the need for a monolithic server (like Node.js/Express or Django) serving views, replacing it with client-side hydration (cms-loader) and secure Edge Functions for restricted actions (like sending emails).

2. DATABASE & BACKEND ENGINE (SUPABASE)
================================================================================
The entire database integration lives on the frontend but interacts securely with PostgreSQL through the Supabase client library.

Initialization (e.g., admin.js Lines 1-5):
```javascript
const SUPABASE_URL = "https://nnwcwqasmdpbvotfepvy.supabase.co";
const SUPABASE_ANON_KEY = "sb_publishable_llEtCRU2fkmNycPY4HwJ5w_XqnkQFQf";
const supabase = window.supabase ? window.supabase.createClient(SUPABASE_URL, SUPABASE_ANON_KEY) : null;
```
Why: The `createClient` function initializes the connection. The `SUPABASE_ANON_KEY` is a public, publishable key. It is completely safe to expose in the frontend because Supabase relies on PostgreSQL Row Level Security (RLS) policies to ensure that this public key can only read/write data if the user has the correct authentication session token.

Advanced Query Example: Fetching Logs with Pagination (admin.js)
```javascript
let query = supabase.from('admin_logs').select('*', { count: 'exact' });
if (logsFilterEntity) query = query.eq('entity_type', logsFilterEntity);
if (logsFilterAction) query = query.eq('action', logsFilterAction);
if (logsSearchQ) query = query.or(`description.ilike.%${logsSearchQ}%,user_email.ilike.%${logsSearchQ}%,entity_id.ilike.%${logsSearchQ}%`);
query = query.order('created_at', { ascending: false }).range(from, to);

const { data: logs, count, error } = await query;
```
Line-by-Line Breakdown:
- `let query = ...`: Instantiates a chained query builder.
- `{ count: 'exact' }`: Instructs the Postgres database to calculate the total number of rows matching the query. This is computationally slightly heavier than a heuristic count, but strictly necessary for accurate UI pagination.
- `.eq('entity_type', logsFilterEntity)`: Appends a SQL `WHERE entity_type = 'X'` clause dynamically.
- `.or(...)`: Appends a SQL `WHERE (col1 ILIKE '%X%' OR col2 ILIKE '%X%')`. `ILIKE` is PostgreSQL's case-insensitive pattern matching.
- `.order(...)`: Maps to SQL `ORDER BY created_at DESC`.
- `.range(from, to)`: Maps to SQL `LIMIT x OFFSET y`. The client calculates the start index and end index based on the page number.

3. AUTHENTICATION & ROLE-BASED ACCESS CONTROL (RBAC)
================================================================================
The app strictly enforces access through the `user_roles` table, bridging the Supabase `auth.users` system with application logic.

Checking Authentication & Role (admin.js):
```javascript
const { data: { session }, error: sessionError } = await supabase.auth.getSession();

if (!session) {
  window.location.href = 'auth.html?redirect=admin.html';
  return;
}

const { data: roleData, error } = await supabase
  .from('user_roles')
  .select('role')
  .eq('user_id', state.user.id)
  .single();
```
Line-by-Line Breakdown:
- `await supabase.auth.getSession()`: Checks the browser's local storage for a valid JWT token issued by Supabase Auth.
- If no session, it immediately redirects the user.
- If a session exists, it queries the `user_roles` table explicitly matching the `user_id` to the currently authenticated user's UUID.
- `.single()`: Ensures the database returns exactly one object, throwing an error if multiple or zero roles are found.

Why: Supabase handles the cryptography of the session (JWT validation). The app then handles the business logic (RBAC). The database RLS policies prevent a user from fetching someone else's role.

Assigning Roles Securely via RPC (admin.js):
```javascript
const { error } = await supabase.rpc('assign_role_by_email', { user_email: email, assigned_role: role });
```
Why: Because `auth.users` (where emails and UUIDs are mapped) is highly restricted, a frontend user cannot natively query it to assign a role to a colleague. By using a Remote Procedure Call (`rpc`), the client triggers a custom SQL function stored on the database server. That server-side function runs with elevated privileges (`SECURITY DEFINER`), securely resolves the email to a UUID, and inserts the role.

4. CUSTOM VISUAL CMS ENGINE
================================================================================
This is the most innovative part of the system. Instead of PHP or Next.js rendering HTML from a database, the system allows visual editing and stores the DOM state in JSON.

Saving Data (cms-editor.js):
```javascript
const fields = {};
document.querySelectorAll('[data-cms-field]').forEach(el => {
  fields[el.dataset.cmsField] = el.innerHTML;
});
// ... Similar loops for images (converting to Base64), buttons, and cards.
const payload = { _editor: true, fields, images: imageDataMap, cards: CARDS };
localStorage.setItem(STORAGE_KEY, JSON.stringify(payload));
```
Why: When the admin double-clicks text, the `contentEditable` flag is toggled. When they hit save, the script iterates over the DOM, capturing the exact HTML string. It builds a massive `payload` dictionary, stringifies it, and stores it in `localStorage` under keys like `sedco_cms_home`.

Loading Data (cms-loader.js - runs on production pages):
```javascript
function apply() {
  const data = loadData(); // reads from localStorage
  if (!data) return;

  if (data.fields) {
    Object.keys(data.fields).forEach(key => {
      const el = document.querySelector('[data-cms-field="' + key + '"]');
      if (el) el.innerHTML = data.fields[key];
    });
  }
}
```
Why: This is "Client-Side Hydration." The static `index.html` loads instantly from the CDN. Milliseconds later, `cms-loader.js` intercepts the DOM, maps the saved JSON keys back to their HTML nodes, and overwrites `innerHTML`. This gives the appearance of a dynamic website with the speed of a static one.

Handling Lucide Icon Edge-Cases (cms-editor.js):
```javascript
function bindIconFields() {
  document.querySelectorAll('[data-cms-icon]').forEach(el => {
    const parent = el.parentElement;
    const key = el.getAttribute('data-cms-icon');
    parent.setAttribute('data-cms-icon-key', key);
  });
}
```
Why: Lucide.js replaces `<i data-lucide="zap">` with a raw `<svg>` tag. If the CMS attached event listeners to the `<i>` tag, they would be destroyed. To solve this, the CMS script executes *before* Lucide initializes. It extracts the data attribute and moves it up to the stable `parentElement`.

5. IN-BROWSER IDE & CODE EDITOR (admin.js)
================================================================================
The admin panel features a fully functional IDE without relying on third-party libraries like Monaco.

Building the Bundle:
```javascript
function buildEditorBundle(files) {
  return files.map(f => `/* === ${f.path} === */\n${f.content}`).join('\n\n');
}
```
Why: The editor allows the user to edit multiple CSS or JS files simultaneously in a single `<textarea>`. It concatenates them, inserting structural markers (`/* === filepath === */`) between them.

Splitting the Bundle:
```javascript
function splitEditorBundle(value, files) {
  const markerRegex = /\/\* === (.+?) === \*\/\r?\n?/g;
  const matches = [...value.matchAll(markerRegex)];
  
  return files.map((file, index) => {
    const match = matches[index];
    const contentStart = match.index + match[0].length;
    const contentEnd = index + 1 < matches.length ? matches[index + 1].index : value.length;
    let content = value.slice(contentStart, contentEnd);
    return { ...file, content: content.trim() };
  });
}
```
Line-by-Line Breakdown:
- `markerRegex`: A regex that searches for the exact string pattern generated in the build function.
- `matches`: Extracts the start index of every marker.
- The loop iterates through the known file list. It calculates the `contentStart` (end of the marker) and `contentEnd` (start of the next marker, or end of string).
- `.slice()` extracts the exact chunk of code belonging to that file.

Why: Because the browser cannot save files directly to the host server, the system saves the separated strings back to `localStorage`. The admin clicks "Download," and the system generates local Blob objects, initiating an automatic download of the source files.

6. 3D EARTH INTEGRATION & WEBGL (globe.js)
================================================================================
The interactive 3D earth uses the `three.js` library.

The Custom Atmosphere Shader:
```javascript
const vs = `
  varying vec3 vNormal;
  void main(){
    vNormal = normalize(normalMatrix * normal);
    gl_Position = projectionMatrix * modelViewMatrix * vec4(position,1.0);
  }`;
const fs = `
  varying vec3 vNormal;
  void main(){
    float i = pow(0.6 - dot(vNormal, vec3(0,0,1)), 2.0);
    gl_FragColor = vec4(0.85, 0.1, 0.1, 0.85) * i;
  }`;
const mat = new THREE.ShaderMaterial({ vertexShader: vs, fragmentShader: fs, blending: THREE.AdditiveBlending, side: THREE.BackSide, transparent: true });
```
Why: Standard materials process light evenly. This custom GLSL (OpenGL Shading Language) uses a dot-product mathematical calculation (`dot(vNormal, vec3(0,0,1))`) to determine how much a pixel is facing the camera. Edges face away (approaching 0), and centers face toward (approaching 1). By manipulating this, it creates the "Fresnel effect"—a glowing halo around the edge of the planet, colored red (`vec4(0.85, 0.1, 0.1)`).

Pulsing Ring Mathematics:
```javascript
for (const r of this.pulseRings) {
  const s = 1 + 0.55 * Math.sin(t * r.speed + r.phase);
  r.mesh.scale.setScalar(s);
  r.mesh.material.opacity = 0.5 * Math.max(0, 1 - (s - 1) / 0.55);
}
```
Line-by-Line Breakdown:
- `t` is the elapsed time.
- `Math.sin(t * speed + phase)`: A sine wave generates a continuous, smooth oscillation between -1 and 1.
- `s`: The scale of the ring geometry oscillates between 0.45 and 1.55.
- `opacity`: As the scale (`s`) increases, the opacity geometrically decreases towards 0, simulating a dissipating energy wave.

Why: Using trigonometric functions tied to elapsed time is the most mathematically performant way to calculate continuous physics on the GPU/CPU without maintaining massive animation state objects.

7. ADVANCED LOGGING & AUDIT SYSTEM
================================================================================
Every mutation in the admin panel triggers `logAction` (admin.js).

```javascript
async function logAction(action, entityType, entityId, description, metadata = {}) {
  if (!state.user) return;
  try {
    await supabase.from('admin_logs').insert([{
      user_id: state.user.id,
      user_email: state.user.email,
      action,
      entity_type: entityType,
      entity_id: entityId || null,
      description,
      metadata
    }]);
  } catch (e) { console.warn('Log failed:', e); }
}
```
Why: By centralizing the logging, the entire application adheres to a strict schema (`action`, `entityType`, `metadata`). The `try/catch` block ensures that if the database logging fails, the parent function (e.g., fulfilling a customer order) succeeds without interruption.

8. CONTACT FORMS & SECURE EMAIL SYSTEM
================================================================================
The app features two distinct email mechanisms:

1. Verification (OTP) via auth.signInWithOtp (contact.js)
```javascript
const { error: otpError } = await supabase.auth.signInWithOtp({ 
  email, options: { captchaToken: captchaToken }
});
```
Why: Before inserting contact data into the database, it utilizes Supabase's native OTP (One-Time Password) system to verify the user owns the email address, thwarting spam bots.

2. Admin Email Dispatch via Edge Functions (admin.js)
```javascript
await supabase.functions.invoke('send-email', {
  body: {
    to: order.customer_email,
    subject: 'Order Confirmed',
    html: `<p>Dear ${order.customer_name}, ...</p>`
  }
});
```
Why: SMTP credentials (like a SendGrid API key) cannot be embedded in client-side Javascript, as they would be stolen. Supabase Edge Functions act as a secure, invisible middleman. The frontend triggers the function, and the secure function server constructs and dispatches the raw email.

9. COMPLETE FILE DIRECTORY BREAKDOWN
================================================================================

Root HTML Files:
- index.html: The primary entry point. Contains the hero section, the 3D globe container, and the structural categories grid.
- about.html, solutions.html, contact.html, marketplace.html: Production views for the specific routes.
- admin.html: The secured gateway to the dashboard. Includes the sidebar, dynamic view container, and login overlay.
- *_for_edit.html: Exact replicas of the production files but with `cms-editor.js` injected at the bottom, enabling the visual DOM manipulation.

CSS Architecture (/css/):
- style.css: Global variables (colors, fonts), resets, buttons, and utility classes.
- admin.css: The massive stylesheet powering the dashboard, the data tables, the modal overlays, and the code editor UI.
- cms-editor.css: Handles the specific floating toolbars, the popovers, and the glowing borders when an admin is editing an element.
- Specific route CSS (home.css, contact.css, etc.): Scoped styles to prevent global namespace pollution.

JS Engine (/js/):
- admin.js: The brain of the backend. Handles routing, RBAC, Data fetching, Logging, the Code Editor, and the Globe Manager.
- cms-editor.js: The brain of the Visual CMS. Attaches event listeners to the DOM, parses JSON payloads, and handles file uploads (converting files to base64 strings).
- cms-loader.js: The client-side hydrator. Runs on live pages to inject the JSON data stored by the editor back into the DOM.
- globe.js: The WebGL / Three.js engine executing the rendering pipeline for the 3D interactive map.
- auth.js: Handles the user-facing login/registration and Cloudflare Turnstile CAPTCHA verification.
- contact.js: Intercepts form submissions, triggers OTP verification, and inserts secure data into Supabase.

CONCLUSION

This architecture is a masterpiece of modern web engineering. By shifting the CMS logic entirely to the client-side (Local Storage & DOM Parsing) and shifting the backend security to Edge Functions and RPCs, the project achieves the perfect balance: the unassailable performance and zero-cost scaling of a static site, combined with the full, dynamic power of an enterprise administrative dashboard.
