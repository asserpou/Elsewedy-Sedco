A. Advanced Pagination & Filtering (admin.js - renderLogs)
----------------------------------------------------------
Code Snippet:
```javascript
let query = supabase.from('admin_logs').select('*', { count: 'exact' });
if (logsFilterEntity) query = query.eq('entity_type', logsFilterEntity);
if (logsFilterAction) query = query.eq('action', logsFilterAction);
if (logsSearchQ) query = query.or(`description.ilike.%${logsSearchQ}%,user_email.ilike.%${logsSearchQ}%,entity_id.ilike.%${logsSearchQ}%`);
query = query.order('created_at', { ascending: false }).range(from, to);

const { data: logs, count, error } = await query;
```

Step-by-Step Explanation:
1. It initializes a base query against the `admin_logs` table, requesting all columns (`*`) and an `exact` total count of rows matching the query (bypassing the need for a separate count query).
2. It dynamically chains `.eq()` (equals) filters if the user has selected a specific entity type or action.
3. If there is a search query, it uses `.or()` with `.ilike()` (case-insensitive `LIKE`) to search across multiple columns simultaneously.
4. It sorts the results by newest first and applies pagination using `.range(from, to)`.

The 'Why':
Building queries dynamically ensures that you only ask the database for exactly what you need. Requesting `{ count: 'exact' }` is a highly optimized way in PostgreSQL/Supabase to get the total number of records for pagination math without fetching all the actual data payloads, saving massive amounts of bandwidth.

B. Secure Role Assignment via RPC (admin.js)
--------------------------------------------
Code Snippet:
```javascript
const { error } = await supabase.rpc('assign_role_by_email', { 
  user_email: email, 
  assigned_role: role 
});
```

Step-by-Step Explanation:
1. Instead of doing a standard `.insert()` or `.update()`, the client calls `.rpc()` (Remote Procedure Call).
2. It passes the target user's email and the new role to a custom PostgreSQL function named `assign_role_by_email` stored on the database.

The 'Why':
Security and Data Integrity. The client does not (and should not) have raw write access to the `user_roles` table or the `auth.users` table. By using an RPC, the backend executes a secure SQL function that can run with elevated privileges (SECURITY DEFINER) to look up the user's UUID by their email and assign the role, ensuring admins cannot arbitrarily tamper with raw user IDs.

D. Splitting the Code Editor Bundle (admin.js)
----------------------------------------------
Code Snippet:
```javascript
function splitEditorBundle(value, files) {
  const markerRegex = /\/\* === (.+?) === \*\/\r?\n?/g;
  const matches = [...value.matchAll(markerRegex)];
  
  return files.map((file, index) => {
    const match = matches[index];
    const contentStart = match.index + match[0].length;
    const contentEnd = index + 1 < matches.length ? matches[index + 1].index : value.length;
    let content = value.slice(contentStart, contentEnd);
    return { ...file, content: content.trim() };
  });
}
```

Step-by-Step Explanation:
1. The custom code editor concatenates multiple CSS or JS files into a single `<textarea>` for easy editing, separated by comment markers (e.g., `/* === css/home.css === */`).
2. When saving, this function uses a Regular Expression (`markerRegex`) to find all these markers.
3. It iterates through the files, slices the massive text block between the current marker and the next marker, and maps the extracted string back to the specific file object.

The 'Why':
Building a multi-tab, multi-file code editor from scratch in a single `<textarea>` is notoriously difficult. This concatenation/splitting algorithm is a highly creative workaround. It provides the UX of editing multiple files simultaneously while maintaining the strict separation of files required for the final download and deployment.

A. Custom Atmospheric Shader (globe.js)
---------------------------------------
Code Snippet:
```javascript
const vs = `
  varying vec3 vNormal;
  void main(){
    vNormal = normalize(normalMatrix * normal);
    gl_Position = projectionMatrix * modelViewMatrix * vec4(position,1.0);
  }`;
const fs = `
  varying vec3 vNormal;
  void main(){
    float i = pow(0.6 - dot(vNormal, vec3(0,0,1)), 2.0);
    gl_FragColor = vec4(0.85, 0.1, 0.1, 0.85) * i;
  }`;

const mat = new THREE.ShaderMaterial({
  vertexShader: vs,
  fragmentShader: fs,
  blending: THREE.AdditiveBlending,
  side: THREE.BackSide,
  transparent: true,
});
```

Step-by-Step Explanation:
1. `vs` (Vertex Shader): Calculates the normal (direction) of each vertex relative to the camera.
2. `fs` (Fragment Shader): Uses the dot product of the normal and the camera's view vector (`vec3(0,0,1)`). It calculates the "Fresnel effect"—making the edges of the sphere glow brighter than the center. It colors the glow a branded red (`vec4(0.85, 0.1, 0.1...)`).
3. `mat`: Creates a custom Three.js material using these GLSL shaders, applying Additive Blending (which adds colors together for a light-emitting effect) and rendering it on the `BackSide` of a slightly larger sphere.

The 'Why':
Standard Three.js materials cannot create a realistic, glowing atmosphere. Writing raw GLSL (OpenGL Shading Language) allows you to mathematically calculate lighting at the pixel level based on the camera angle, resulting in a highly professional, cinematic halo effect that matches the brand's aesthetic.

B. Additive Blending & Animation Loop (globe.js)
------------------------------------------------
Code Snippet:
```javascript
// In _buildMarkers
const ring = new THREE.Mesh(
  new THREE.RingGeometry(size * 1.8, size * 2.5, 48),
  new THREE.MeshBasicMaterial({
    color, transparent: true, opacity: 0.6, blending: THREE.AdditiveBlending, depthWrite: false
  })
);

// In _loop
for (const r of this.pulseRings) {
  const s = 1 + 0.55 * Math.sin(t * r.speed + r.phase);
  r.mesh.scale.setScalar(s);
  r.mesh.material.opacity = 0.5 * Math.max(0, 1 - (s - 1) / 0.55);
}
```

Step-by-Step Explanation:
1. It creates 2D rings around the 3D pins. `depthWrite: false` ensures the glowing rings don't cause weird visual clipping artifacts with other transparent objects.
2. In the animation loop, it uses a Sine wave (`Math.sin()`) combined with the elapsed time (`t`) to continuously cycle the scale (`s`) of the ring between 1.0 and 1.55.
3. It dynamically fades the opacity as the ring gets larger, simulating a dissipating radar pulse.

The 'Why':
Using `Math.sin()` is a standard, highly performant way to create infinite, smooth oscillating animations in game development. Combined with `AdditiveBlending`, it creates a holographic "hight-tech" feel.

A. The Pre-Lucide Icon Binding Strategy (cms-editor.js)
-------------------------------------------------------
Code Snippet:
```javascript
function bindIconFields() {
  document.querySelectorAll('[data-cms-icon]').forEach(el => {
    const parent = el.parentElement;
    const key = el.getAttribute('data-cms-icon');
    parent.setAttribute('data-cms-icon-key', key);
    // ...
  });
}
```

Step-by-Step Explanation:
1. The CMS allows admins to double-click icons to change them.
2. However, the Lucide library automatically destroys `<i data-lucide="x">` tags and replaces them with raw `<svg>` tags, destroying any attached event listeners or custom data attributes.
3. To solve this, this script runs *before* Lucide initializes. It finds the icon, reads the `data-cms-icon` attribute, and moves that data up to the parent HTML element as `data-cms-icon-key`.

The 'Why':
This is a brilliant edge-case solution. Third-party libraries that mutate the DOM often break custom interactive scripts. By intercepting the DOM and shifting the state up to a stable parent element, the CMS retains the ability to identify and replace the icon even after Lucide has completely rewritten the underlying HTML.

B. The Surgical DOM Injection (cms-loader.js)
---------------------------------------------
Code Snippet:
```javascript
if (data.buttons) {
  Object.keys(data.buttons).forEach(key => {
    const el = document.querySelector('[data-cms-btn="' + key + '"]');
    const b = data.buttons[key];
    if (b.text !== undefined) {
      const childEls = Array.from(el.children).map(c => c.cloneNode(true));
      el.textContent = '';
      if (b._iconFirst && childEls.length) {
        childEls.forEach(c => el.appendChild(c));
        el.appendChild(document.createTextNode(' ' + b.text));
      } else {
        el.appendChild(document.createTextNode(b.text + ' '));
        childEls.forEach(c => el.appendChild(c));
      }
    }
  });
}
```

Step-by-Step Explanation:
1. When applying saved data to a production page, it finds buttons by their `data-cms-btn` key.
2. Instead of just replacing the `innerHTML` (which would delete any SVG icons inside the button), it carefully extracts the child elements (the icons).
3. It clears the button, and then reconstructs the button by appending the saved text and re-appending the cloned child icons, respecting whether the icon was originally on the left or right side (`_iconFirst`).

The 'Why':
This demonstrates a deep understanding of DOM manipulation. Naively overriding `innerHTML` is a common mistake that breaks layouts. This code surgically targets only the text node while preserving the complex structural integrity of the surrounding components.
